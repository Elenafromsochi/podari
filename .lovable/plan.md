## Что делаем

Заменяем текущий Telegram Login Widget на поток «открыл бота → нажал Подтвердить». Никакого кода вводить не нужно — фронт сам поймёт, что вход подтверждён, и залогинит.

## Поток пользователя

1. На экране входа одна большая кнопка **«Войти через Telegram»**.
2. По нажатию открывается `t.me/Podari_podarki_bot?start=<nonce>` (в новой вкладке/в приложении Telegram).
3. В боте пользователь жмёт **Start** → бот отвечает: «Подтверди вход в Подари» и две inline-кнопки: **✅ Это я** / **🚫 Не я**.
4. Пользователь жмёт «Это я» → бот пишет «Готово, возвращайся в приложение».
5. Сайт всё это время опрашивает сервер (раз в 1.5 сек). Как только видит `status=approved` — сразу подтягивает сессию и логинит. Если новый пользователь — создаётся автоматически (имя/username из Telegram), +1 балл, реферал отрабатывает как сейчас.

Состояния на экране входа:
- «Открой бота и подтверди вход» (с повторной кнопкой и QR-кодом deep-link для десктопа)
- «Подтверждение получено, входим…»
- Ошибки: ссылка устарела / отклонено → предложить попробовать снова.

## Технические изменения

**БД (миграция):**
- В `auth_nonces`: добавить `approved_at timestamptz` и `rejected_at timestamptz`. Поле `code` больше не используется в новом потоке (оставляем nullable для совместимости со старыми ссылками из ботом-отправленных писем, можно потом удалить).

**Server functions (`src/lib/telegram-auth.functions.ts`):**
- `startTelegramLogin` — оставить как есть (возвращает `nonce` + `deep_link`).
- `pollTelegramLogin` — расширить статусами: `waiting` → `opened` (когда юзер нажал Start, но ещё не подтвердил) → `approved` / `rejected` / `expired`.
- Новый `completeTelegramLogin({ nonce })` — вызывается фронтом, когда poll вернул `approved`. Внутри: проверяет `approved_at`, создаёт/находит supabase-юзера по `telegram_id`, применяет реферал, помечает nonce `consumed_at`, возвращает `access_token`/`refresh_token`. Логика по сути перенесённая из текущего `verifyTelegramCode`, только без проверки кода.
- `verifyTelegramCode` — удаляем (или оставляем deprecated на пару дней).

**Webhook бота (`src/routes/api/public/telegram/webhook.ts`):**
- При `/start <nonce>`: находит nonce, проставляет `telegram_id`/`username`/`first_name`, отправляет сообщение «Подтверди вход» с inline-клавиатурой (`callback_data: approve:<nonce>` и `reject:<nonce>`).
- Добавить ветку `update.callback_query`: парсит `callback_data`, проверяет, что `from.id` совпадает с `telegram_id` в nonce, ставит `approved_at`/`rejected_at`, отвечает `answerCallbackQuery` + редактирует сообщение («✅ Вход подтверждён, возвращайся в приложение»).
- Реферальная ветка `ref_<uuid>` остаётся — после привязки реферала бот теперь не шлёт код, а сразу показывает кнопку «Подтвердить вход».

**Фронт:**
- `src/components/AuthFlow.tsx` — убрать `TelegramLoginButton`/`widgetSignIn`. Сделать новый компонент `BotConfirmFlow`: кнопка «Войти через Telegram» → вызывает `startTelegramLogin` → открывает deep-link и начинает polling `pollTelegramLogin` каждые 1.5 сек до 5 минут → при `approved` вызывает `completeTelegramLogin`, ставит сессию, грузит профиль.
- `src/components/TelegramLoginButton.tsx` — удалить.
- `src/lib/telegram-widget.functions.ts` и `telegram-widget.server.ts` — удалить.
