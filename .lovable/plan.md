
# Система уровней и экономика «Подари»

Большая переработка экономики. Хочу зафиксировать все правила прежде чем кодить — пропусти спорные моменты в конце.

## 1. Новая экономика баллов

**Баллы (gift points)** — теперь дробные, шаг 0.1. В БД храним как `numeric(10,2)`.
Стартовый баланс новых пользователей: **1 балл** (вместо 100).

Начисления:
- Получение подарка: −1 балл, +10 XP
- Отзыв авто-шаблоном (получатель): +5 XP
- Отзыв письменный/голосовой (получатель): +20 XP
- Размещение подарка: +20 XP, +0.2 балла
- Приглашение друга: +50 XP пригласившему, +1 балл другу
- Вручение подарка (подтверждение получателем): +0.8 балла, +80 XP дарителю
- Отзыв авто-шаблоном (даритель): +5 XP
- Отзыв письменный/голосовой (даритель): +20 XP

Стоимость любого подарка для получателя: **1 балл** (раньше было 100).

## 2. Уровни

| Lvl | XP диапазон | Что открывается |
|-----|-------------|-----------------|
| 1 | 0–199 | Б/у вещи до 3 000 ₽ |
| 2 | 200–499 | + Время специалиста / знания / опыт |
| 3 | 500–999 | + Угощение (обед, кофе), приглашение на мероприятия |
| 4 | 1000–1699 | + Вещи 3 000–6 000 ₽ |
| 5 | 1700–2499 | + Время специалиста до 6 000 ₽ |

Меняем `calc_level()` в БД на эту таблицу.

## 3. Категории подарков (новые)

Добавляю поле `gift_kind` на gifts: `used_item | specialist_time | treat | event_invite`.
Плюс `price_tier`: `under_3k | 3k_to_6k` (для вещей и времени специалиста).
При публикации форма даёт выбрать только те типы/тиры, которые доступны на текущем уровне пользователя.
Сервер дополнительно валидирует.

## 4. Новое авто-сообщение

В `ReviewModal` (и аналог для дарителя) добавляю третий пресет:
**«Сделка отменилась / что-то пошло не так 😕»** — +5 XP, без штрафов.

## 5. Отзыв дарителя о получателе

Сейчас `ReviewModal` показывается только получателю. Добавляю зеркальный поток для дарителя после `confirmHandover`:
- «Всё прошло отлично, получатель добродушный и благодарный! 🌿»
- «Хорошо, но есть нюансы… 💬»
- «Что-то пошло не так 😕»
Те же правила XP (5 за пресет, 20 за свой текст/голос).

## 6. Общая лента сделок

Новая вкладка/экран **«Лента»** (на главной, рядом с подарками).
Показывает завершённые сделки в реальном времени:
- фото подарка, название, имя дарителя, «вручил подарок», время.
Источник: `transactions` со `status='completed'` + join `gifts` + `profiles(sender)`.
Realtime через `supabase.channel` на UPDATE transactions.
Публично видна всем авторизованным.

## 7. Onboarding-подсказки (опционально)

После каждого ключевого действия сервис подсказывает следующий шаг (получил → отзыв → размести свой → пригласи друга → вручи). Реализую как лёгкий банер в кабинете на основе профиля (есть ли размещённый подарок, есть ли приглашённый друг и т.д.). **Приглашение друга** — нужен реферальный механизм: ссылка `t.me/<bot>?start=ref_<userId>`, при первом входе нового пользователя засчитываем реферала. Сделаю минимальную версию: поле `referred_by` в profiles, начисление при первой авторизации.

## 8. Миграция данных

- `profiles.balance` → `numeric(10,2) default 1`
- `gifts.cost` → `numeric(10,2) default 1`
- `gifts` + `gift_kind`, `price_tier`, `price_rub` (для проверки лимитов)
- `profiles` + `referred_by uuid`
- Обновляю SQL функции `claim_gift`, `confirm_handover`, `award_publish_xp`, `award_review_xp`, `calc_level`, `handle_new_user`.
- Включаю realtime для `transactions`.
- Все существующие демо-пользователи: balance пересчитываю (старые 100 → 1, плюс XP не трогаю).
