## Что делаем

Меняем модель входа: вместо «каждый раз код из Telegram» — **логин по @username и паролю**. Telegram остаётся как канал доставки одноразового кода, но запрашивается только когда человек входит с **нового/неизвестного устройства**. На знакомом устройстве — просто пароль.

Пароль становится обязательным для всех (миграция).

---

## Сценарии пользователя

**1. Новый пользователь регистрируется**
1. Жмёт «Войти», далее «Я тут впервые».
2. Открывается Telegram-бот, нажимает Start, бот шлёт 4-значный код (как сейчас).
3. Вводит код → попадает на экран «Придумай пароль» → задаёт пароль (мин. 8 символов).
4. Это устройство автоматически становится доверенным на 30 дней.

**2. Существующий пользователь (после релиза)**
1. Старого пароля нет. На главной форме «Забыл пароль / войти через Telegram» — старый флоу (бот → код).
2. После входа — обязательный экран «Задай пароль» (нельзя пропустить). Устройство становится доверенным.
3. В следующий раз сразу входит по @username + паролю.

**3. Обычный вход с доверенного устройства**
- Поля: «@username» и «пароль» → жмёт «Войти» → внутри приложения. Никаких кодов.

**4. Вход с нового устройства**
1. Вводит @username и пароль → проверка пароля проходит.
2. Сервер видит, что `device_id` (из localStorage) не в списке доверенных → шлёт код в Telegram-бот этому пользователю и показывает экран «Введи код из Telegram».
3. Пользователь вводит код → сессия выдаётся, устройство добавляется в доверенные на 30 дней.
4. Чекбокс «Запомнить это устройство» включён по умолчанию; если снять — код будут спрашивать каждый раз.

**5. Забыл пароль**
- Кнопка «Забыл пароль» → Telegram-флоу как при регистрации → после входа экран «Задай новый пароль».

**6. Управление устройствами (бонус, минимально)**
- В личном кабинете список доверенных устройств (last_seen, expires_at) с кнопкой «Отозвать». Если человек потерял телефон — отзывает все.

## Изменения в базе

**Миграция:**
- `profiles`: добавить `password_set boolean not null default false`.
- Новая таблица `trusted_devices`: `user_id uuid`, `device_id text`, `label text` (UA/платформа), `created_at`, `last_seen_at`, `expires_at timestamptz`. PK `(user_id, device_id)`. RLS: владелец видит/удаляет свои.
- Новая таблица `device_login_codes`: `user_id uuid`, `code text` (4 цифры), `device_id text`, `attempts int default 0`, `expires_at` (5 минут), `consumed_at`. RLS: deny-all (работаем через `supabaseAdmin`).
- Индекс `profiles(lower(telegram_username))` для быстрого поиска по @nick.

## Серверные функции (createServerFn)

- `loginWithPassword({ username, password, device_id })`:
  - находим `profile` по `telegram_username` (без учёта регистра) → получаем внутренний `email = tg_<tg_id>@tg.podari.local`,
  - `signInWithPassword(email, password)`. Если ошибка — «Неверный логин или пароль».
  - проверяем `trusted_devices`: если запись есть и не истекла → возвращаем `{ status: 'ok', access_token, refresh_token }`, обновляем `last_seen_at`.
  - иначе: генерируем 4-значный код, пишем в `device_login_codes`, шлём через Telegram-бот в чат `telegram_id` (gateway `sendMessage`) текстом «Код входа: 1234», и **сразу делаем `signOut`** на серверной сессии. Возвращаем `{ status: 'need_2fa', challenge_id }` (без токенов).
- `confirmDeviceCode({ challenge_id, code, device_id, remember, user_agent })`:
  - валидируем код, лимит 5 попыток, TTL 5 мин,
  - снова `signInWithPassword` → если `remember`: вставляем `trusted_devices` с `expires_at = now() + 30 days`,
  - помечаем код consumed, возвращаем токены.
- `setPassword({ password })` (middleware `requireSupabaseAuth`):
  - валидация (≥8 символов), `supabaseAdmin.auth.admin.updateUserById(userId, { password })`,
  - `update profiles set password_set = true`,
  - текущее устройство (по присланному `device_id`) добавляем в `trusted_devices`.
- `listTrustedDevices()` и `revokeTrustedDevice({ device_id })` — для экрана управления.
- Существующий `verifyTelegramCode` остаётся для регистрации/восстановления пароля; после его успеха клиент проверяет `password_set` и принудительно ведёт на `/set-password`.

## Изменения на клиенте

- `src/lib/device-id.ts` — стабильный `device_id` в `localStorage` (`crypto.randomUUID`).
- `src/components/AuthFlow.tsx` — три шага: `password` (по умолчанию), `2fa` (код Telegram при новом устройстве), `telegram` (текущий флоу — теперь под кнопкой «Войти через Telegram / Забыл пароль»). На шаге `password`: поля `@username` + `пароль` + чекбокс «Запомнить это устройство». При `need_2fa` → шаг `2fa` с OTP-полями.
- Новый роут `/set-password` (под `_authenticated`-гейтом) — экран «Придумай пароль». Гейт в `__root` / на главном лейауте: если профиль загружен и `password_set === false` → редирект на `/set-password` (нельзя пользоваться приложением).
- `loadUser()` дочитывает `password_set`.
- В кабинете — небольшая секция «Устройства» со списком и кнопкой «Отозвать».

## Безопасность и edge-cases

- Пароль валидируем zod-схемой (минимум 8, максимум 128); включаем HIBP-проверку (`configure_auth` → `password_hibp_enabled: true`).
- Защита от перебора кода: 5 попыток на `challenge_id`, после — invalidate.
- Сообщение об ошибке логина — общее («Неверный логин или пароль»), чтобы не палить, существует ли @username.
- `device_id` — не секрет, это просто идентификатор; реальный фактор доверия — что сервер сам добавил его в `trusted_devices` после успешной 2FA.
- При смене пароля — опция «Выйти со всех устройств» (чистит `trusted_devices` для user_id).
- Истёкшие `trusted_devices` чистим лениво при логине.

## Что НЕ трогаем

- Реферальную логику, очки, балансы — без изменений.
- Старый Telegram-бот webhook и `auth_nonces` — остаются для регистрации и сброса пароля.
- Сессии текущих авторизованных пользователей не разлогиниваем; они увидят экран «Задай пароль» при следующем взаимодействии (или сразу, если уже залогинены — гейт сработает).
